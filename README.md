# Gymbro's

**Track your grind. See your progress.**

Личный трекер тренировок в зале для двух человек. Веб‑приложение, рассчитанное на телефон:
iPhone (Safari) и Android (Chrome). Интерфейс на русском.

## Что умеет

- Вход по почте и паролю, два независимых аккаунта, регистрации нет.
- Главная: приветствие, дата, тренировки и время в зале за месяц, последняя тренировка, личные рекорды.
- Активная тренировка на отдельном экране: таймер от времени начала, упражнения, подходы (вес и повторения),
  порядок упражнений, подсказка «в прошлый раз». Всё сохраняется само и переживает перезагрузку,
  закрытие браузера и пропавшую сеть.
- Итоги перед сохранением, сравнение с прошлыми тренировками и сообщения о прогрессе.
- История, календарь, просмотр, правка и удаление сохранённых тренировок.
- Страница упражнения: рекорды, максимум повторений на каждом весе, график динамики.
- Светлая и тёмная темы, установка на экран «Домой».

## Технологии

Next.js 16 (App Router, Server Actions, Route Handler) · TypeScript · Tailwind CSS 4 ·
Supabase (Postgres + Auth, RLS) · Radix UI · Lucide · Zod · Vitest. Хостинг — Vercel.

Нужен **Node.js 22 или новее**.

## Устройство проекта

```
app/
  (auth)/login            вход
  (app)/                  разделы с нижней навигацией: главная, календарь, история,
                          тренировка (просмотр), упражнение, профиль
  (focus)/workout         активная тренировка — на весь экран
  (focus)/workouts/[id]/edit   правка сохранённой тренировки
  api/workouts/[id]/sync  автосохранение и завершение тренировки
  api/auth/signout        выход из аккаунта
components/               интерфейс (ui/ — базовые элементы, workout/ — редактор тренировки)
lib/
  actions.ts              Server Actions (вход, профиль, упражнения, старт и удаление тренировки)
  data.ts                 чтение данных (только на сервере)
  auth.ts, supabase/      сессия и клиент Supabase
  workout-editor.ts       логика редактора (чистые функции)
  workout-sync.ts         черновик на устройстве и синхронизация с сервером
  progress/insights.ts    правила сравнения с прошлыми тренировками
  dates.ts, format.ts     часовые пояса и русское форматирование
proxy.ts                  обновление сессии и редирект гостей на /login
supabase/migrations/      схема базы, политики RLS, функции
docs/01-design.md         проектный документ: архитектура, база, сценарии
docs/02-device-checklist.md   чек-лист проверки на телефоне (12 шагов)
docs/screenshots/         снимки экранов с демо-данными
```

Как защищены данные:

- браузер не обращается к Supabase напрямую — только сервер приложения;
- каждая серверная операция проверяет сессию, а в базе на всех таблицах включён RLS:
  пользователь видит и меняет только свои строки;
- пароли хранит и проверяет Supabase Auth, в приложении их нет;
- сервисный (secret / service_role) ключ приложению не нужен и нигде не используется;
- cookie с сессией — `HttpOnly`, `SameSite=Lax`, на Vercel ещё и `Secure`.

## Переменные окружения

| Переменная | Что это | Где взять |
| --- | --- | --- |
| `SUPABASE_URL` | Адрес проекта Supabase | Project Settings → Data API → Project URL |
| `SUPABASE_PUBLISHABLE_KEY` | Публичный ключ (`sb_publishable_…`; подойдёт и старый `anon`) | Project Settings → API Keys |

Обе переменные читаются только на сервере. Префикс `NEXT_PUBLIC_` не нужен — в браузер они не попадают.
Шаблон лежит в `.env.example`. Файлы `.env*` (кроме шаблона) в git не попадают.

## Развёртывание

### 1. Supabase

1. Создайте проект на [supabase.com](https://supabase.com) (регион — ближайший к вам, например Frankfurt).
2. Примените миграции из `supabase/migrations/` **по порядку**. Любым способом:
   - **SQL Editor**: откройте по очереди `…01_schema.sql`, `…02_rls.sql`, `…03_functions.sql`,
     вставьте содержимое и нажмите Run;
   - **Supabase CLI**: `npx supabase link --project-ref <ref>` и затем `npx supabase db push`.
3. Создайте два аккаунта: **Authentication → Users → Add user → Create new user**.
   Укажите почту и пароль и включите **Auto Confirm User**. Профиль для каждого создаётся автоматически.
   Третьего пользователя база создать не даст (`user_limit_reached`).
4. Закройте регистрацию: **Authentication → Sign In / Providers** → выключите **Allow new users to sign up**.
5. Скопируйте Project URL и Publishable key — они понадобятся на следующем шаге.

Имя, которое показывается в приветствии, каждый меняет сам в разделе «Профиль». Там же можно сменить пароль.

### 2. Vercel

1. Загрузите проект в репозиторий на GitHub (файл `.env.local` в репозиторий не попадёт).
2. На [vercel.com](https://vercel.com): **Add New → Project**, выберите репозиторий. Настройки сборки менять не нужно.
3. В **Environment Variables** добавьте `SUPABASE_URL` и `SUPABASE_PUBLISHABLE_KEY`.
4. Нажмите **Deploy**. Версия Node.js — 22 или новее (Settings → General → Node.js Version).

### 3. Телефон

Откройте адрес сайта и войдите. Чтобы приложение открывалось как обычное, на весь экран:

- **iPhone (Safari)**: «Поделиться» → «На экран „Домой“».
- **Android (Chrome)**: меню ⋮ → «Добавить на главный экран» / «Установить приложение».

После первого входа пройдите короткий чек-лист `docs/02-device-checklist.md` — он проверяет то,
что видно только на настоящем телефоне: клавиатуры, безопасные зоны, восстановление тренировки.

## Как работает автосохранение тренировки

Во время тренировки каждое изменение сразу записывается в память телефона (черновик), а через
мгновение уходит на сервер целиком. Если сети нет, приложение показывает «На телефоне» и
повторяет отправку, когда связь вернётся — в том числе после перезагрузки страницы или
повторного входа. Таймер не «тикает» счётчиком, а каждый раз вычисляется как «сейчас минус время
начала», поэтому блокировка экрана ему не мешает.

Без сети нельзя *открыть* приложение с нуля (офлайн‑оболочки в этой версии нет) — но уже открытая
тренировка продолжает работать и ничего не теряет.

## Правила сравнения с прошлыми тренировками

- учитываются только сохранённые тренировки, которые были раньше текущей;
- сравнивается одно и то же упражнение из личного списка;
- первое выполнение упражнения — точка отсчёта, а не рекорд;
- повторения сравниваются только при одинаковом весе;
- для упражнений без отягощения сравниваются повторения и подходы, но не вес и объём;
- приложение сообщает только об улучшениях; длительность — нейтрально и только при заметной разнице.
