## 0. Ключевые решения коротко

| Тема | Решение |
|---|---|
| Приложение | Один Next.js-проект (App Router, TypeScript), без отдельного бэкенда |
| Данные | Supabase Postgres, доступ только с сервера Next.js, RLS на всех таблицах |
| Авторизация | Supabase Auth (email + пароль), экрана регистрации нет, регистрация отключена в Supabase |
| Активная тренировка | Черновик живёт на телефоне (localStorage) и автоматически синхронизируется с сервером целым снимком |
| Таймер | Считается как «сейчас − started_at», а не счётчиком |
| Прогресс | Вычисляется на лету из сохранённых тренировок, ничего не кэшируется и не хранится отдельно |
| PWA | Манифест + иконки (установка на домашний экран), без service worker в первой версии |
| Секреты | Ключи Supabase читаются только на сервере; service/secret-ключ в приложении не используется вовсе |

### 1.2. Слои

```

│  Серверные страницы (чтение)  +  клиентские компоненты (ввод, таймер, темы)
```

### 1.3. Принципы доступа к данным

- **Браузер не обращается к Supabase напрямую.** Все запросы идут через сервер Next.js, поэтому в клиентском коде нет ни одного ключа.
- **Каждая серверная операция проверяет пользователя** через `supabase.auth.getClaims()` (проверяет подпись токена). `proxy.ts` — только удобство (редирект), а не граница безопасности.
- **RLS — вторая, независимая линия защиты.** Запросы выполняются от имени вошедшего пользователя, и даже ошибка в коде приложения не даст доступа к чужим строкам.
- **Составные изменения — атомарно.** Сохранение тренировки (упражнения + подходы) выполняется одной Postgres-функцией в транзакции: либо сохранилось всё, либо ничего.

### 1.4. Активная тренировка: сохранность данных

Это самая ответственная часть, поэтому описана подробно.

**Источник истины во время тренировки — черновик на устройстве.** Каждое изменение мгновенно попадает в интерфейс и в localStorage, затем отправляется на сервер.

1. **Запись.** Изменение → состояние экрана → localStorage (сразу) → отложенная на ~1 с отправка снимка всей тренировки на `POST /api/workouts/{id}/sync`.
2. **Снимок, а не отдельные операции.** Отправляется вся тренировка целиком (это десятки строк). Операцию можно безопасно повторять, порядок запросов не важен, «потерянных правок» не бывает.
3. **Нет сети.** Отправка не удалась → черновик помечен как несинхронизированный → повтор при появлении сети, при возврате на вкладку и по таймеру с нарастающей паузой. Пользователь видит статус: «Сохранено» / «Сохраняю…» / «Нет сети — сохранено на телефоне».
4. **Сворачивание и закрытие.** При уходе со страницы снимок отправляется запросом с `keepalive`, который браузер доводит до конца даже после закрытия вкладки.
5. **Возврат.** Сервер отдаёт сохранённую версию. Если на устройстве есть несинхронизированный черновик — побеждает он и сразу отправляется; иначе берётся серверная версия. Значит, тренировку можно продолжить и с другого устройства.
6. **Истекла сессия.** Черновик не трогаем, просим войти заново, после входа синхронизируем.
7. **Таймер.** `started_at` хранится в базе; на экране — разница с текущим временем, пересчёт раз в секунду и при возврате на вкладку. Блокировка телефона на него не влияет.

**Честное ограничение.** Без service worker полностью перезагрузить страницу при отсутствии сети нельзя — браузер покажет свою офлайн-страницу. Данные при этом не теряются: они в localStorage и подтянутся, когда сеть вернётся. Уже открытый экран тренировки продолжает работать без сети. См. вопрос 3 в разделе 11.

**Одна активная тренировка.** Гарантируется базой: частичный уникальный индекс по `user_id` для строк со статусом `active`. Повторное нажатие «Начать» (двойной тап, вторая вкладка) открывает существующую.

**Забытая тренировка.** Если активная тренировка длится больше 6 часов, главная предлагает: продолжить, завершить с указанием реального времени окончания или удалить.

### 1.5. Время и часовые пояса

- В базе всё хранится как `timestamptz` (UTC).
- Часовой пояс устройства записывается в cookie; сервер использует его для границ месяца, раскладки календаря по дням и форматирования. Это убирает расхождения «сервер в UTC, телефон в Москве».
- Тренировка относится к дню, в который она **началась** (по часовому поясу устройства), даже если закончилась после полуночи.
- Все преобразования — в одном модуле `lib/dates.ts`, покрыты тестами.

### 1.6. Авторизация и ограничение регистрации

- Вход: email + пароль через Supabase Auth. Пароли хранит и проверяет только Supabase.
- В приложении **нет** экрана регистрации.
- В Supabase отключается «Allow new users to sign up». Два аккаунта создаются вручную в панели Supabase (шаги будут в инструкции).
- Страховка в базе: триггер не даёт создать больше двух профилей. Даже если регистрацию случайно включат, третий аккаунт не появится.
- Профиль создаётся автоматически триггером при создании пользователя.

### 1.7. PWA и мобильные особенности

- `manifest` (название, иконки, `display: standalone`, цвета темы), `apple-touch-icon`, корректный `theme-color` для обеих тем.
- `viewport-fit=cover` и отступы `env(safe-area-inset-*)` — контент и нижняя навигация не попадают под «чёлку» и индикатор жестов.
- Высота экранов — в `dvh`, чтобы экранная клавиатура и панель Safari не ломали вёрстку.
- Поля ввода — шрифт от 16 px (иначе iOS Safari приближает страницу при фокусе).
- Вес: `inputmode="decimal"`, принимаются и «62,5», и «62.5» (русская клавиатура даёт запятую). Повторения: `inputmode="numeric"`.
- Зоны нажатия — не меньше 44×44 px, основные действия — в нижней половине экрана.

## 3. База данных

### 3.1. Схема

```
auth.users ──1:1── profiles
     │
     ├──1:N── exercises ◄─────────────┐ (exercise_id, при удалении → NULL)
     │                                │
     └──1:N── workouts ──1:N── workout_exercises ──1:N── workout_sets
                        (каскад)                 (каскад)
```

### 3.2. Таблицы

**profiles**

| Поле | Тип | Ограничения |
|---|---|---|
| id | uuid | PK |
| user_id | uuid | UNIQUE, FK → auth.users, ON DELETE CASCADE |
| display_name | text | 1–40 символов |
| created_at | timestamptz | default now() |

**exercises** — личный список упражнений

| Поле | Тип | Ограничения |
|---|---|---|
| id | uuid | PK |
| user_id | uuid | FK → auth.users, ON DELETE CASCADE |
| name | text | 1–60 символов; уникально для пользователя без учёта регистра |
| created_at | timestamptz | default now() |

Триггер: не больше **30** упражнений на пользователя (проверяется в базе, а не только в интерфейсе).

**workouts**

| Поле | Тип | Ограничения |
|---|---|---|
| id | uuid | PK |
| user_id | uuid | FK → auth.users, ON DELETE CASCADE |
| started_at | timestamptz | NOT NULL |
| finished_at | timestamptz | NULL, пока тренировка активна; ≥ started_at |
| duration_seconds | integer | Вычисляемая колонка: finished_at − started_at (не может разойтись с датами) |
| status | text | `active` \| `completed`; `completed` ⇔ finished_at заполнено |
| created_at, updated_at | timestamptz | updated_at обновляется триггером |

Индексы: `(user_id, started_at desc)`; **уникальный частичный** `(user_id) where status = 'active'`.

**workout_exercises**

| Поле | Тип | Ограничения |
|---|---|---|
| id | uuid | PK (генерируется на устройстве — нужно для синхронизации) |
| workout_id | uuid | FK → workouts, ON DELETE CASCADE |
| exercise_id | uuid | FK → exercises, ON DELETE SET NULL |
| exercise_name_snapshot | text | NOT NULL — название на момент тренировки |
| position | integer | ≥ 0, уникально в пределах тренировки |

**workout_sets**

| Поле | Тип | Ограничения |
|---|---|---|
| id | uuid | PK |
| workout_exercise_id | uuid | FK → workout_exercises, ON DELETE CASCADE |
| set_number | integer | ≥ 1, уникально в пределах упражнения |
| weight | numeric(6,2) | 0…999.99 кг; 0 = без отягощения |
| reps | integer | 1…999 |

Количество подходов не ограничено малым числом (технический потолок — 50 на упражнение, как защита от мусорных данных).

### 3.3. Поведение при изменениях

- **Переименование упражнения** меняет только `exercises.name`. История показывает `exercise_name_snapshot` и не меняется.
- **Удаление упражнения из списка** не трогает историю: в старых тренировках остаётся название, связь обнуляется. Статистика прогресса по удалённому упражнению больше не ведётся — перед удалением будет предупреждение.
- **Удаление тренировки** каскадно удаляет её упражнения и подходы.
- **Удаление пользователя** каскадно удаляет все его данные.

### 3.4. Функции и представление

Все функции выполняются с правами вызывающего пользователя (RLS действует внутри них).

| Объект | Назначение |
|---|---|
| `start_workout()` | Создаёт активную тренировку или возвращает уже существующую |
| `save_workout(id, payload, expect_status, finish, started_at, finished_at)` | Одна функция на автосохранение, завершение и правку сохранённой тренировки — всё в одной транзакции (отдельной `finish_workout` в итоге нет) |
| `workout_exercise_stats` (view) | По каждому упражнению в завершённой тренировке: число подходов, сумма повторений, объём, максимальный вес |
| Триггеры | Автосоздание профиля, лимит 2 профиля, лимит 30 упражнений, `updated_at` |

### 3.5. RLS

RLS включён на всех пяти таблицах. Роль `anon` не имеет доступа ни к чему.

| Таблица | Правило для SELECT / INSERT / UPDATE / DELETE |
|---|---|
| profiles | `user_id = auth.uid()`; INSERT и DELETE из приложения запрещены (профиль создаёт триггер) |
| exercises | `user_id = auth.uid()` |
| workouts | `user_id = auth.uid()` |
| workout_exercises | Родительская тренировка принадлежит пользователю; `exercise_id` пуст либо указывает на **своё** упражнение |
| workout_sets | Через упражнение → тренировку: тренировка принадлежит пользователю |

Представление `workout_exercise_stats` создаётся с `security_invoker`, поэтому тоже подчиняется RLS. Миграции будут сопровождаться SQL-скриптом проверки: пользователь A не может прочитать, изменить или удалить строки пользователя B.

## 4. Экраны и навигация

**Нижняя навигация (телефон):** Главная · Календарь · История · Профиль.
На экранах от 768 px она превращается в боковое меню, контент центрируется в колонке комфортной ширины.

| Маршрут | Экран | Содержание |
|---|---|---|
| `/login` | Вход | Email, пароль, понятные ошибки |
| `/` | Главная | Приветствие и дата; тренировок за месяц; время в зале за месяц; последняя тренировка (дата, длительность, упражнения); блок прогресса (последние рекорды); кнопка «Начать тренировку» или «Продолжить тренировку · 00:42:10» |
| `/calendar` | Календарь | Месячная сетка, переключение месяцев, отметки на днях с тренировками, выделение сегодняшнего дня; тап по дню → список тренировок этого дня (одна или несколько) → детали |
| `/history` | История | Список от новых к старым, сгруппированный по месяцам: дата, длительность, число упражнений и подходов |
| `/workouts/[id]` | Детали | Итоги, прогресс по сравнению с прошлым, все упражнения и подходы; «Редактировать», «Удалить» (с подтверждением) |
| `/workouts/[id]/edit` | Правка | Тот же редактор, что в активной тренировке, плюс время начала и окончания |
| `/workout` | Активная тренировка | Отдельный полноэкранный режим, см. ниже |
| `/exercises/[id]` | Упражнение | Рекорды, график динамики, последние выполнения |
| `/profile` | Профиль | Имя, тема, список упражнений (добавить, переименовать, удалить; счётчик N/30), выход |

Календарь и история связаны: обе ведут на одну страницу деталей; из деталей можно перейти к дню в календаре.

### Экран активной тренировки

```
┌──────────────────────────────────┐
│ ←  Тренировка          ● Сохранено│
│         00:42:17                 │
│      начало в 18:05              │
├──────────────────────────────────┤
│ 1 · Жим лёжа               ↑ ↓ ⋯ │
│ В прошлый раз (4 ноя):           │
│ 60×12 · 70×10 · 70×8 · 75×6      │
│                                  │
│  1   [ 60  кг ]  ×  [ 12 ]    ✕  │
│  2   [ 70  кг ]  ×  [ 10 ]    ✕  │
│  3   [ 72,5 кг ]  ×  [ 8 ]    ✕  │
│        + Подход                  │
├──────────────────────────────────┤
│ 2 · Тяга верхнего блока    ↑ ↓ ⋯ │
│  …                               │
├──────────────────────────────────┤
│ [ + Упражнение ]   [ Завершить ] │
└──────────────────────────────────┘
```

Принципы ввода:

- **«+ Упражнение»** открывает нижнюю шторку со списком личных упражнений (недавние сверху, поиск по названию). Один тап — упражнение добавлено. Новое название вводится в той же шторке и сразу попадает в личный список.
- **«+ Подход»** создаёт подход с уже подставленными значениями: из предыдущего подхода, а для первого — из прошлой тренировки. Чаще всего достаточно поправить одно число.
- Подход добавляется, когда он выполняется; отдельной галочки «выполнено» нет.
- Значения правятся вводом с цифровой клавиатуры или кнопками «−» и «+» (шаг веса 2,5 кг, повторений 1).
- Порядок упражнений меняется кнопками ↑ ↓ — на телефоне это надёжнее перетаскивания.
- Удаление упражнения с подходами — с подтверждением; удаление одного подхода — сразу, с возможностью отмены в уведомлении.
- Незаполненный подход (нет веса или повторений) хранится только в черновике; при завершении приложение попросит дозаполнить его или удалить.

## 5. Пользовательские сценарии

**1. Вход.** Открыл приложение → `/login` → email и пароль → Главная. Сессия долгая, повторный вход нужен редко.

**2. Начало тренировки.** Главная → «Начать тренировку» → создаётся активная тренировка, фиксируется время начала → экран `/workout` с идущим таймером.

**3. Запись.** «+ Упражнение» → выбор из списка → видна подсказка «В прошлый раз…» → «+ Подход» → правка веса и повторений → следующий подход. Всё сохраняется автоматически.

**4. Перерыв в процессе.** Закрыл браузер, обновил страницу, пропала сеть → открыл снова → на главной «Продолжить тренировку» → всё на месте, таймер показывает реальное время с начала.

**5. Завершение.** «Завершить» → экран итогов: дата, начало, окончание, длительность, число упражнений, подходов, повторений, полный список → «Сохранить тренировку» или «Вернуться к тренировке». Этот двухшаговый переход и есть защита от случайного завершения: до подтверждения ничего не закрывается, таймер продолжает идти.

**6. После сохранения.** Открывается страница тренировки с блоком прогресса: рекорды и сравнение с прошлым разом, короткое уведомление о главном достижении.

**7. Отмена.** Случайно начал → меню «⋯» → «Отменить тренировку» → подтверждение → тренировка удалена. Попытка завершить пустую тренировку предлагает именно это.

**8. Просмотр.** Календарь → день → тренировка. Или История → тренировка.

**9. Правка.** Детали → «Редактировать» → изменения → «Сохранить». Прогресс пересчитывается автоматически, потому что вычисляется на лету.

**10. Удаление.** Детали → «Удалить» → подтверждение → запись исчезает из истории и календаря.

**11. Список упражнений.** Профиль → «Мои упражнения» → добавить, переименовать, удалить. При 30 упражнениях добавление блокируется с понятным сообщением.

**12. Тема.** Профиль → тёмная / светлая / как в системе. Выбор сохраняется на устройстве.

## 6. Прогресс и достижения

### 6.1. Что считается

Для каждого упражнения в завершённой тренировке:

| Показатель | Определение |
|---|---|
| Максимальный рабочий вес | Наибольший вес среди подходов |
| Повторения на весе | Наибольшее число повторений в одном подходе с данным весом |
| Подходы | Количество подходов |
| Объём | Сумма «вес × повторения» по всем подходам |
| Динамика | Ряд значений (макс. вес, объём) по датам тренировок |

### 6.2. С чем сравнивается

- **«Прошлый раз»** — ближайшая более ранняя **завершённая** тренировка, где было это же упражнение.
- **Рекорд** — сравнение со всеми более ранними завершёнными тренировками.
- Сравнение идёт по `exercise_id`, а не по тексту названия, поэтому переименование не разрывает историю.
- Активная тренировка в расчётах не участвует, пока не сохранена.

### 6.3. Правила корректности

- Первое выполнение упражнения — не рекорд. Показывается нейтрально: «Первая запись — точка отсчёта».
- Повторения сравниваются **только при одинаковом весе**. «10 повторений с 60 кг» и «8 с 70 кг» не сравниваются.
- Для упражнений без веса (вес 0) сравниваются только повторения и подходы; объём и вес — нет.
- Длительность сравнивается с предыдущей завершённой тренировкой и упоминается, только если разница от 5 минут; формулировка нейтральная.
- Уведомления — только о росте. Снижение результатов видно на графике и в деталях, но приложение о нём не «сообщает».
- Не больше 4 сообщений на тренировку, по приоритету: рекорд веса → рекорд повторений на весе → рекорд объёма → больше повторений, чем в прошлый раз → больше подходов → длительность.

### 6.4. Примеры сообщений

- «Новый рекорд в жиме лёжа: 80 кг — на 5 кг больше прежнего»
- «Жим лёжа, 70 кг: 10 повторений — на 2 больше, чем в прошлый раз»
- «Приседания: на один подход больше»
- «Рекордный объём в тяге: 3 240 кг»
- «Тренировка длилась на 15 минут дольше предыдущей»

### 6.5. Где это видно

| Место | Что показано |
|---|---|
| Активная тренировка | Под названием упражнения — подходы прошлого раза |
| После завершения / детали тренировки | Блок «Прогресс» с сообщениями и отметками рекордов у подходов |
| Главная | 2–3 последних рекорда |
| Страница упражнения | Рекорды, график, история выполнений |

Логика — чистые функции в `lib/progress`, покрытые юнит-тестами на все правила из 6.3. Объёмы данных малы (два пользователя, сотни тренировок в год), поэтому расчёт на лету не требует отдельных таблиц.

## 7. Дизайн

**Идея:** приложение выглядит как точный измерительный прибор, а не как рекламный фитнес-шаблон. Главные герои экрана — цифры.

- **Тёмная тема:** тёплый графит (не чистый чёрный), карточки на тон светлее фона, тонкие границы вместо теней.
- **Светлая тема:** тёплый почти-белый фон, белые карточки, тот же характер.
- **Один акцентный цвет**, используется экономно: главная кнопка, сегодняшний день, отметки тренировок, рекорды. Предложение — «вольт» (жёлто-лаймовый) с тёмным текстом на нём; в светлой теме он работает как заливка, а не как цвет текста. Альтернативы — в вопросе 1.
- **Типографика:** гротеск с кириллицей, крупные цифры одинаковой ширины (таймер и веса не «прыгают»), мало начертаний, чёткая иерархия.
- **Без визуального шума:** никаких стоковых фото, градиентов-пятен и декоративных иконок. Иконка — только там, где помогает найти действие.
- **Движение:** короткие переходы (150–250 мс) для шторок, появления подхода, уведомлений; заметная, но короткая анимация при рекорде. Учитывается системная настройка «уменьшить движение».
- **Состояния:** скелетоны при загрузке, осмысленные пустые экраны («Пока нет тренировок — начни первую»), понятные ошибки с кнопкой повтора.

## 8. Безопасность и надёжность

| Требование | Как обеспечивается |
|---|---|
| Проверка авторизации | В каждой серверной операции + RLS в базе |
| Чужие данные недоступны | RLS на всех таблицах, проверочный SQL-скрипт |
| Секреты | Только переменные окружения сервера; в клиентский код ключи не попадают; `.env*` в `.gitignore` |
| Посторонние аккаунты | Регистрация выключена в Supabase + лимит двух профилей в базе |
| Потеря данных | Черновик на устройстве + автосинхронизация + атомарное сохранение |
| Две активные тренировки | Уникальный частичный индекс |
| Некорректный ввод | Zod на сервере + ограничения CHECK в базе |
| Ошибки | Уведомления об успехе и ошибках, экран ошибки с повтором, статус синхронизации |

**Переменные окружения**

| Переменная | Назначение |
|---|---|
| `SUPABASE_URL` | Адрес проекта Supabase |
| `SUPABASE_PUBLISHABLE_KEY` | Публичный ключ (`sb_publishable_…`), действует только в рамках RLS |

Secret-ключ (бывший `service_role`) приложению не нужен и нигде не используется.

## 10. Что не входит

По ТЗ не делаем: соцсети, чаты, ленту, подписки, платежи, питание, программы тренировок, интеграции с браслетами.

## 11. Вопросы на согласование

Для каждого указан вариант по умолчанию — если устраивает, достаточно ответить «ок».

1. **Акцентный цвет.** По умолчанию — «вольт» (жёлто-лаймовый) на графите. Альтернативы: коралловый/оранжевый или электрический синий.
2. **Стартовый список упражнений.** По умолчанию — список пуст, вы и Олег добавляете упражнения сами при первой тренировке. Альтернатива: пришлите ваши ~14 названий, и они будут предзаполнены обоим.
3. **Офлайн.** По умолчанию — без service worker (проще и надёжнее; ограничение описано в 1.4). Альтернатива: добавить офлайн-оболочку, чтобы экран тренировки открывался вообще без сети, — это заметно усложняет проект, и я бы отложил это до первых недель реального использования.
4. **Смена пароля в профиле.** В ТЗ её нет. По умолчанию — добавить простую смену своего пароля (иначе менять можно только через панель Supabase). Альтернатива: не добавлять.
5. **Правка времени сохранённой тренировки.** По умолчанию — при редактировании можно исправить время начала и окончания (на случай, если забыли нажать «Завершить»). Альтернатива: править только упражнения и подходы.

## 12. Версия 2: сплиты и тренировки друга

Дополнение, согласованное после запуска первой версии. Всё, что описано выше, остаётся в силе.

### 12.1. Сплиты

- Сплит — именованный список упражнений из личного списка, со своим порядком. До 12 сплитов на человека,
  название до 40 символов, до 30 упражнений в сплите. Названия не повторяются (без учёта регистра).
- Управление — в профиле. Список сплитов свёрнут: строка с названием раскрывается по касанию и показывает
  упражнения, кнопки «Изменить» и удаления. Создание и правка — в окне, выезжающем снизу:
  название, упражнения с перестановкой, поиск по своему списку и добавление нового упражнения на месте.
- В тренировке: пока она пустая, сплиты показаны крупными кнопками; позже они доступны в окне
  «+ Упражнение» в блоке «Сплит целиком». Касание добавляет все упражнения сплита по порядку.
- Упражнения из сплита добавляются **без подходов** — подходы и веса вносятся как обычно.
  Упражнение, в котором не осталось ни одного заполненного подхода, в сохранённую тренировку не попадает;
  экран итогов предупреждает об этом. Пропущенное упражнение удалять вручную не нужно.
- Название первого загруженного сплита становится названием тренировки и показывается в истории,
  календаре, на главной и на странице тренировки. Второй сплит добавляет только недостающие упражнения,
  название остаётся прежним. Если убрать из тренировки все упражнения, название сбрасывается.
- Название хранится в самой тренировке (`workouts.split_name`), поэтому переименование или удаление сплита
  не меняет прошлые записи. Удаление упражнения из личного списка убирает его и из сплитов.

### 12.2. Тренировки друга

- В профиле — блок «Друг» со ссылкой «Тренировки: <имя>». Экраны `/friend` (список по месяцам,
  «Показать ещё») и `/friend/<id>` (время, итоговые числа, упражнения с подходами).
- Только просмотр и только сохранённые тренировки. Не видны: незавершённая тренировка, личный список
  упражнений, сплиты, рекорды и графики друга. Сравнений, рейтингов и ленты нет.
- Доступ открыт обоим всегда, отдельной настройки нет.

### 12.3. База данных

Одна дополнительная миграция `20261114000004_splits_and_friend.sql`, первые три не меняются:

- `workouts.split_name text null` — название сплита на момент тренировки;
- `splits (id, user_id, name, created_at, updated_at)`, `split_exercises (split_id, exercise_id, position)`;
  RLS «только свои строки», лимит 12 сплитов проверяет триггер;
- `save_split(p_split_id, p_name, p_exercise_ids)` — создаёт сплит или целиком заменяет его состав;
- `save_workout(…, p_split_name)` — седьмой необязательный параметр: `null` — не менять, пустая строка — сбросить;
- `friend_display_name()`, `friend_workouts(p_limit)`, `friend_workout(p_workout_id)` — чтение для друга.
  Это `security definer`‑функции: они отдают только завершённые тренировки второго участника,
  ничего не изменяют и доступны только вошедшим пользователям. Политики RLS на таблицах при этом
  остаются прежними — напрямую чужие строки по‑прежнему не читаются и не меняются.
